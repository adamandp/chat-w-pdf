# 002 revision results

Implemented 2026-10-19. Application changes are confined to `frontend/`; this report is in root `docs/res/`. Pre-existing backend edits, removed reports, the supplied prompt, archive, and manually supplied Annual Report PDF were left untouched.

## Changes

- Added App Router paths `/`, `/documents`, and `/trash`, with pathname-based navigation. WorkspaceProvider preserves selected/new chat state across navigation.
- Split MockProvider and QueryProvider. MockProvider gates children until browser MSW startup resolves, so initial Axios/TanStack queries cannot race worker activation. `initMocks()` is idempotent; its server branch is called only explicitly in server/test contexts. A client effect does not start the server. Startup errors show a retry action.
- Audited `instant` against the installed Next.js 16.4 documentation. It is a real Cache Components navigation/static-shell validation option, unrelated to starting MSW. Removing it produced `instant-unrendered-segment` warnings because the readiness gate hides page children during validation. Retained `instant = false` on the root layout and pages, with comments explaining that dependency. `cacheComponents` and `partialPrefetching` remain enabled.
- Dropdowns use the existing shadcn/Base UI primitive with nonmodal overlay behavior, 10px offset, wider content, and distinct selected/hover colors. Clicking the trigger again closes it without moving chat bubbles.
- Extracted message display/edit/feedback into ChatMessages and library selection into DocumentLibrary. Editing has an explicit input border/focus outline and outlined Cancel button.
- Added shared resizable primitive backed by react-resizable-panels. Desktop side preview stays within 20–40%; expanded PDF puts chat on the right within 20–40%. The separator supports pointer and keyboard interaction. Existing mobile preview overlay and PDF controls remain. Stable chat panel identity preserves search/edit state when opening or changing preview mode.
- Added recent chat search and inline See All/See Less below the list; expanded results scroll vertically. Existing document icon/brand assets remain consistent; no Document Library sidebar entry was added.
- Documents grid/list share API-backed pagination and page state; search/sort reset the page. Chat History and Documents History each own page state and distinct query keys. Mutation invalidation refreshes both legacy selectors and paginated lists.
- Moved types to domain interfaces under `features/`, removed global `types/`, centralized Axios in `lib/axios.ts`, split services by domain, and separated MSW domain fixtures and handlers. Kept a small API facade for the existing workspace hook rather than adding redundant hooks.

## Configuration and usage

From `frontend/`: `bun install`, then `bun run dev`.

Mocking defaults to enabled for this demo. Set `NEXT_PUBLIC_API_MOCKING=disabled` to bypass startup and use real requests. `NEXT_PUBLIC_API_URL` overrides the default `/api` Axios base URL. Configure those together when using another server; bundled handlers match `/api` on the local origin.

Browser mocking uses `public/mockServiceWorker.js`. `mocks/server.ts` exports the explicit Node test server. The root layout composes MockProvider, QueryProvider, and WorkspaceProvider. Requests flow through service APIs and TanStack Query; components do not read fixtures.

Place PDFs in `frontend/public/pdfs/` using fixture filenames, such as `Annual Report 2023.pdf`, `Annual Report 2022.pdf`, or `Financial Analysis.pdf`. The viewer URL encodes the filename. Missing files show the existing fallback. Uploaded mock files create metadata; their bytes are not persisted to the static directory. The regression suite creates and removes its own separate `e2e-preview-test.pdf`, without overwriting the supplied PDF.

## API contract

Existing endpoint methods/payloads remain unchanged. No new endpoint paths were introduced.

| Method | Path under `/api` | Input / result |
| --- | --- | --- |
| GET | `/sessions` | `deleted=false/true`; Session array by default |
| GET | `/sessions/:id/chats` | Message array |
| GET | `/sessions/:id/documents` | Active related PdfDocument array |
| PATCH | `/sessions/:id` | `{title}`; updated Session |
| GET | `/documents` | `deleted=false/true`; PdfDocument array by default |
| POST | `/chats` | Multipart `message`, `sessionId`, `mode`, JSON `documentIds`, optional `document` PDF file; 201 `{session,messages}` |
| POST | `/chats/:id/edit` | JSON `{message}` only; updated user Message |
| POST | `/feedback` | `{messageId,rating: "up" or "down"}`; 201 `{id,messageId,rating}` |
| DELETE | `/sessions/:id`, `/documents/:id` | Soft delete by default; `permanent=true` hard deletes; 204 without body |
| POST | `/sessions/:id/restore`, `/documents/:id/restore` | Restored entity |

Optional pagination extends GET `/sessions` and `/documents`: when `page` is present, parameters are `page`, `pageSize`, `search`, `sort`, and `deleted`. Name search matches titles for sessions and filenames for documents. Documents support `Last modified`, `Name`, and `Page count`. Requests without `page` keep the original array responses for existing selectors and contract compatibility.

Example paged response: `{ "data": [], "paging": { "currentPage": 1, "pageSize": 3, "totalItems": 0, "totalPages": 1 } }`. The common `WebResponse<T>` allows optional `message`, `errors`, `data`, and `paging`. Page numbers clamp to the available range after deletion. Error responses retain `{message}` with HTTP 400/404/500. `/error` as a chat message exercises the existing simulated failure.

## Limits

Pagination reference images in 002 are empty placeholders; the shared Previous/page-count/Next design follows the existing visual style. Mock data remains in memory and resets on full reload. The fixture set has four initial active chats; creating more chats makes the expanded list longer. MSW simulates answers and does not analyze PDFs. Missing sample PDFs intentionally log 404 viewer warnings during fallback tests; a supplied PDF shorter than its metadata can briefly report an invalid initial page before the existing load-success clamp. These warnings did not fail the suite. No live backend integration was attempted.
